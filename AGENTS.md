# AIN-Loop framework repository

## Product and architecture

- `scripts/ain.py` is the zero-dependency Python runtime and source of truth.
- `bin/ain` is the distribution entry point; `config/`, `templates/`, `prompts/`, and `integrations/` are packaged resources.
- `.ain/` is this repository's dogfood installation. Refresh it from the source distribution; do not hand-patch `.ain/runtime/ain.py`.
- `ai/changes/` records framework changes through the same lifecycle the framework enforces.
- The universal core must remain platform and vendor neutral. Put product-specific checks in a consuming repository's configuration, not here.

## Commands

- Unit/regression tests: `python3 -m unittest -v tests/test_ain.py`
- Syntax check: `python3 -m py_compile scripts/ain.py`
- Install into a scratch repository: `./bin/ain --target /path/to/repo init --with-github`
- Dogfood status: `./.ain/ain status CHG-20260828-001`
- Check a planned diff: `./.ain/ain guard --change CHG-20260828-001`
- Execute and check evidence: `./.ain/ain verify CHG-20260828-001 --kind unit --command 'python3 -m unittest -v tests/test_ain.py'` then `./.ain/ain verify CHG-20260828-001 --check`

## Non-negotiable rules

- All material framework changes start at `ai/changes/<change-id>/intent.md`; do not modify product paths before the plan is accepted.
- `plan.md` must list narrow `planned_paths`. If scope changes, update and reapprove the plan before changing the new path.
- Keep the worktree clean immediately before a strict approval or `verify` command so its subject commit is unambiguous.
- Do not claim `verification.result: pass` without a successful `ain verify` record for the stated commit. `partial` must retain `release_blocked: true`.
- Use `apply_patch` for source edits and preserve unrelated user changes. Never add network credentials or make the framework depend on a particular vendor service.
- Do not weaken tests, CI, approvals, or Git guard rules to make a change pass; record a consciously accepted exception instead.

## Protected areas

- `scripts/ain.py`, `config/framework.json`, `templates/`, and `integrations/github/ain-gate.yml` evolve together; update tests and docs in the same change.
- `.ain/runtime/`, `.ain/templates/`, `.ain/prompts/`, and `.github/workflows/ain-gate.yml` are generated by `init`; refresh rather than manually drift them.
- Historical `ai/changes/*` artifacts are evidence. Amend them only when the current change explicitly requires it.

## Known agent mistakes

- A local `--by` string is an attestation, not authenticated identity. Do not describe it as identity verification.
- `validate` checks artifacts; use `guard` as well to check source-only diffs.
- Do not use `shell=True` for framework-run verification commands; keep commands as direct argv parsed with `shlex.split`.
